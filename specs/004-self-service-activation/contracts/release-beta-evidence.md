# Contract: Release and Beta Evidence

## Support contract

A machine-readable support matrix names supported Node, OS, surface and package
manager combinations. Public docs render only supported cells; experimental
Yarn/Bun checks are labeled non-blocking.

## Registry verification

Post-publish validation runs the exact documented version from a fresh directory
without workspace links, `file:` dependencies, local tarball substitution or a
repo-seeded cache. Each record captures package integrity/resolution, runtime,
OS, manager, surface, commands, UTC timestamps and sanitized results.

Local packed-artifact and release-candidate checks are useful but have distinct
evidence types and never claim public registry success.

## External beta activation

An external run excludes maintainer, bots, CI, the same organization and paid
synthetic testing. It records classification, public version, environment,
milestone timing, assistance and separately scoped consent. A completed run
requires participant-controlled provider evidence, valid 402, finalized devnet
settlement, protected response and replay rejection.

Downloads, views, stars, clones and synthetic transactions never increment
starts or completions. Public attribution requires separate consent; aggregate
reporting uses a minimum cohort threshold where re-identification is plausible.

## Commercial claim gate

Primary CTA remains the free, uncompensated five-person devnet beta. The USD 100
customer-paid implementation service is separate. It is promoted as the next
primary experiment only after at least three independent installs, two without
critical intervention, median first-402 under ten minutes and one external
settlement plus replay proof. Interest, invoice or willingness-to-pay is not
revenue; only verified received commercial cash is.
